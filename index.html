Executive Summary

This document presents a continuous internet article monitoring and deduplication platform designed to automatically discover, organize, and store relevant web articles by topic.

Key Capabilities

  • Automated continuous monitoring of configured topics
  • Intelligent deduplication (4-layer strategy)
  • Structured storage with audit trails
  • Query access through MCP interface
  • Production-ready architecture

Business Value Proposition

Problem Addressed

Organizations need to stay informed about topics relevant to their business, but manual web searches are:

  • Time-consuming — requires manual effort and repetition
  • Error-prone — duplicates and outdated content mixed with relevant information
  • Difficult to track — no organized repository of discovered information
  • Not scalable — manual process doesn't grow with organization needs

Solution Delivered

A fully automated platform that:

  • Discovers new relevant articles 24/7 without manual intervention
  • Deduplicates intelligently to prevent information pollution
  • Organizes articles by topic with full metadata
  • Preserves complete audit trail for compliance
  • Exposes curated information through structured API (MCP)

Business Outcomes

Faster decision-makingAlways have latest information on monitored topics
Higher data qualityIntelligent deduplication reduces noise
Cost reductionAutomation replaces manual research
ComplianceComplete audit trail and version history
ScalabilitySystem grows without proportional effort increase

Five-Module Architecture

Module 1 — Topic Configuration Manager

Purpose: Allow administrators to define and manage monitored topics

Responsibilities
  • CRUD operations for topics (create, read, update, delete)
  • Store topic preferences (keywords, language, region)
  • Enable/disable topics without code changes
Interaction Pattern
  • REST API endpoint: /api/topics
  • Configuration persisted to MongoDB
  • Cached in-memory for performance
Technology Stack
  • Quarkus REST framework
  • MongoDB Panache ORM
Value Delivered
  • No development effort to add new topics
  • Real-time enable/disable capability

Module 2 — Search Provider Adapter

Purpose: Abstract external search provider integration

Responsibilities
  • Call external search provider (Serper.dev)
  • Transform raw results to canonical format
  • Handle provider failures with retry/fallback
  • Rate limiting and timeout management
Technology Stack
  • Quarkus REST framework
  • Jackson JSON processing
  • Resilience4j (retry/circuit breaker)
  • Secret Manager (API key storage)
Value Delivered
  • Automatic failure handling
  • Secure credential management

Module 3 — Scheduled Search Orchestrator

Purpose: Automate search execution without manual intervention

Responsibilities
  • Schedule searches based on topic frequency
  • Distribute searches throughout day (avoid thundering herd)
  • Orchestrate full processing pipeline
Interaction Pattern
  • Quartz Scheduler manages timing (or Kubernetes CronJobs, depending on deployment)
  • One job iterates through all active topics
  • Different cron expressions per topic
Technology Stack
  • Quartz Scheduler
  • Topic Configuration Manager
  • Search Provider Adapter
Value Delivered
  • Fully automated 24/7 operation
  • No human intervention required
  • Configurable monitoring frequency

Module 4 — Intelligent Deduplication Engine

Purpose: Prevent duplicate/similar content from polluting the knowledge base

Responsibilities
  • Compare new articles against existing database
  • Use a 4-layer strategy: URL hash → Bloom filter → Content hash → Similarity scoring
  • Flag borderline cases for manual review if needed
Comparison Strategy (Priority Order)
#LayerLatencyNotes
1URL Matching< 1 msNormalize URLs, remove tracking parameters; exact hash comparison; 100% accurate for same URL
2Bloom Filter< 1 msFast probabilistic check; avoids expensive DB queries; false positive rate < 1%
3Content Hash< 5 msSHA256 of article snippet; detects reposted/mirrored content; high confidence match
4Similarity Scoring50–100 msTF-IDF based semantic comparison; detects paraphrased versions; only used if first 3 layers pass
Technology Stack
  • Apache Commons Math (similarity algorithms)
  • Guava (Bloom filters)
Value Delivered
  • Reduces duplicate content
  • Multiple detection strategies ensure coverage

Module 5 — MCP Query Server

Purpose: Expose curated articles through a structured API

Responsibilities
  • Provide read-only access to stored articles
  • Support rich filtering (topic, date, relevance, source)
  • Expose topic statistics
Available Queries

Technology Stack
  • Quarkus REST framework
  • MongoDB aggregation pipeline
  • OpenAPI/Swagger documentation
  • MCP protocol support
Value Delivered
  • Downstream systems access curated data
  • AI assistants can consume information
  • Rich querying without database access

Data Model

Collections in MongoDB

Topics
├── _id: ObjectId
├── name: String (display name)
├── keywords: Array[String]
├── language: String (en, pt, etc.)
├── region: String (US, EU, etc.)
├── updateFrequency: String (6h, daily, weekly)
├── lastSearchTime: Date
├── lastSuccessTime: Date
├── active: Boolean
└── timestamps: createdAt, updatedAt

Articles
├── _id: ObjectId
├── title: String
├── url: String (original source)
├── urlHash: String (SHA256)
├── contentHash: String (SHA256)
├── snippet: String (summary)
├── publishedDate: Date
├── source: String (domain)
├── topicIds: Array[ObjectId] (many-to-many)
├── relevanceScore: Number (0.0-1.0)
├── tags: Array[String]
├── metadata: { author, imageUrl, language }
└── timestamps: discoveredAt, createdAt

ProcessingLogs
├── _id: ObjectId
├── topicId: ObjectId
├── executionTime: Date
├── durationMs: Number
├── articlesFound: Number
├── articlesPersisted: Number
├── articlesDeduped: Number
├── status: String (SUCCESS, FAILED, PARTIAL)
└── errorMessage: String (if failed)
